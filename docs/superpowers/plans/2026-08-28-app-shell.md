# App Shell, Navigation & Settings Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the top navbar with a persistent left rail plus an avatar-triggered
profile menu, split settings into AI / Study / Help, add a generated-or-uploaded avatar
and a feedback channel, and redesign every page the rail touches so nothing ships as an
old page in a new frame.

**Architecture:** One Next.js route group `src/app/(app)/` owns the shell; study
activities and auth pages stay outside it and render bare. The root layout stops
supplying `<main>` and its measure, which the shell layout now owns exactly once. Pure
logic (nav active-state, avatar resolution, image sniffing, feedback validation) lives in
`src/lib/**` and is unit-tested without a router, a DOM, or a database.

**Tech Stack:** Next.js 16.2.9 App Router, React Server Components, Prisma 7.8 /
Postgres, `@vercel/blob`, Base UI popover/dialog, Tailwind v4, Vitest 4.

**Spec:** `docs/superpowers/specs/2026-08-28-app-shell-design.md`

## Global Constraints

- **Baselines to hold:** 184 test files / 2241 tests passing, `tsc --noEmit` clean,
  `npm run lint` at 175 problems (do not increase), `next build` compiles.
- **`readableSetWhere` composition rule.** Any new set read composes through
  `composeSetWhere`; never spread it beside another `OR` key.
  (`src/lib/sets/visibility.ts`)
- **Vitest 4 needs a per-file `// @vitest-environment jsdom` docblock.**
  `environmentMatchGlobs` does not work; `vitest.config.ts` documents this.
- **`src/lib/mail/send.ts` MUST NEVER THROW.** Every caller is inside `after()`.
- **Never add the Credentials provider to `src/auth.config.ts`** (edge runtime).
- **`GOOGLE_KEY_ENCRYPTION_SECRET` and the `v1:<iv>:<tag>:<ciphertext>` format are
  frozen.**
- **Every new guard must be proven red by mutation** before its task is done. This repo
  has shipped five guards that could not fail; two of them last session.
